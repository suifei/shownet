# ShowNet 功能全景与工作流

本文盘点产品前后端能力、前后关系与自动化边界，便于开箱使用与二次开发。实现以仓库源码为准。

## 1. 一句话定位

**AI 原生抓包 + 自动证书 + 自动协议逆向 + 一键生成可运行代码。**  
设计原则：能自动化的默认自动化；小白有零配置路径；专家可进高级控制台与 Skill。

## 2. 推荐工作流（抓包 → 证据 → 分析 → 导出）

| 阶段 | 用户做什么 | 产品自动做什么 | 主入口 |
|------|------------|----------------|--------|
| **1 抓包** | 内嵌浏览器开始抓包；或装 CA 后代理手机/App | 会话持久化、MITM 解密、Hook 注入、出站 TLS 预置 | 浏览器 / 设置 / 高级控制台「配置」 |
| **2 证据** | 在流量点开请求 | 关联 Hook、AST 加密片段、TLS 指纹、PX/reCAPTCHA 标记 | 流量 / 高级控制台 |
| **3 分析** | 选模式启动 AI 分析 | Skill 编排、MCP 取证、Graph 阶段、可审计报告 | AI 分析 |
| **4 导出** | 确认报告 / Lab 生成 | 算法重放包、多语言客户端、Auto-crawler、集合导入导出 | 报告 / Request Lab / Skill |

零配置最短路径：**浏览器「开始抓包」→ 看流量 → AI 分析 → 导出代码**（无需先装 CA）。

### 2.1 找不到功能时的两个统一入口

功能分散在 7 个视图和 4 个设置分区里，因此有两条不需要知道「哪个视图管这件事」的路径：

| 入口 | 快捷键 | 覆盖范围 |
|------|--------|----------|
| **命令面板** | `⌘K` / `Ctrl+K` | 全应用操作索引，按「开始使用 / 抓包与连接 / 会话与导出 / 前往 / 设置与证书」分组；支持中文名、英文别名（`ca`、`har`、`ja3`）与拼音首字母；带状态徽章（运行中 / 未安装）与禁用原因 |
| **新手引导** | 顶栏「还差 N 步」按钮，或命令面板「打开新手引导」 | 把抓包、来源、证书、AI 四件事的就绪状态集中到一屏；证书与 AI 标记为可选，只看内嵌浏览器可跳过 |

设置页另有独立搜索框，跨全部 4 个分区检索 13 个设置分组（`src/settingsIndex.ts` 为单一事实来源），
结果标注所属分区，点击直接跳转并展开对应分组。分组展开状态跨分区持久化。

### 2.1.1 两套代码生成的分工

它们看起来重复，实际是两件不同的事，各自独立实现是正确的：

| | Request Lab 代码片段 | 算法模拟包 |
|---|---|---|
| 实现 | `src/requestCode.ts`（TypeScript） | `src-tauri/src/algorithm_replay.rs` 等（Rust） |
| 输入 | 一条请求的 URL / Header / Body | AI 分析还原出的算法与调用链 |
| 输出 | 单个请求的调用片段，供人对照阅读 | **可编译运行**的客户端工程 |
| 目的 | 「这条请求用 Python 怎么写」 | **模拟**而非重放：像浏览器一样走通站点 |

后者的要求要高得多——Cookie / Session 要跨请求保持、HTTP 连接与上下文要复用、
要真正调用还原出的算法而不是塞入抓到的固定签名、要正确组包发包解包。
两个运行时无法共用实现，因此保持两份是有意的，不属于"重复来源"。

### 2.2 功能分组约定

同一件事只从一个地方进入，低频操作收进溢出菜单，破坏性操作写明后果：

| 位置 | 现在的形态 | 之前的问题 |
|------|-----------|-----------|
| **流量 · 筛选** | 单一「筛选」按钮 + 快捷/条件/视图三段面板；工具栏下方展示可逐项移除的生效筛选标签 | 搜索框、方法快捷条、快捷筛选弹层、统计侧栏、条件构建器五处各自写同一个 query，没有合并读数 |
| **流量 · 选中操作** | 网格上方浮动操作栏，主操作带文字标签，其余进「更多」 | 状态栏里 8 个纯图标按钮，只有 tooltip |
| **请求集合 · 集合操作** | 「新建文件夹」「归档抓包」带标签 + 「更多」菜单 | 8 个纯图标按钮，两个导出仅靠图标区分 |
| **高级控制台 · PX** | 单个「PX 证据」页 + 解码/对比/改写模式切换（10 个标签页减为 8 个） | 三个标签页渲染同一个主体、共用同一个计数徽章 |
| **高级控制台 · 出站预置** | 只保留下拉框 | 下拉框与快捷按钮两套控件驱动同一个值 |
| **实验室 · cURL** | 草稿打开时也能从同一个菜单导入 / 导出 | 导入只在空草稿页存在，导出是另一处的图标按钮 |
| **实验室 · 断点** | 「规则」标签带待处理数量徽章 | 有倒计时的实时队列只在进入该标签后才可见 |

### 2.3 界面诚实性约定

界面不呈现做不到的操作，不用相同措辞表示不同作用范围：

- **代理端口**固定为 8888（后端无修改入口），因此按只读事实展示并说明端口占用时怎么办，不再渲染成看似可编辑的输入框。
- **AI 分析**的两个入口分别叫「分析整个会话」和「分析选中」；右键菜单写明选中条数。
- **请求对比**在选中数不为 2 时给出明确空态，而不是渲染「0 项差异」的空壳（那读起来像"两条请求完全相同"）。
- 确认对话框统一为应用内组件（`src/components/ConfirmDialog.tsx`），破坏性操作标红并写明后果；规则启用的凭据与流量影响是其中最需要被读到的文案。
- 实验室的标签沿用流量详情页的中文命名（参数 / 请求头 / 请求体 / 认证），不再中英混排。
- 表格的多列排序、批量选择、列宽拖拽等**原本没有任何提示**的交互，收在 `?` 快捷键与命令面板的「快捷键与鼠标操作」里。
- 设置页的未保存改动会在分区标题打「未保存」标记（折叠时也可见）并在底部常驻汇总条；判定逻辑见 `src/settingsDirty.ts`，以"当前值 vs 后端基线"比较，后端推送与运行时同步不算作编辑。
- 发送选项（跟随重定向 / 验证 TLS / 使用上游代理）的文案由 `src/sendSettings.ts` 统一，实验室与重放不再对同一开关给出不同说明——尤其「验证 TLS」的授权测试警告此前只出现在重放面板。

分析模式名称由 `src/analysisModes.ts` 统一（AI 分析与 Skill 编排曾对同一模式使用不同中文名），
选中的模式由 App 层持有并在两个视图间共享——AI 分析视图切走会卸载，模式选择原本会丢失。

自动恢复最近一份报告**不会**改写模式选择（只有从历史下拉框主动选择才会）；
报告标题描述的是正在显示的那份报告，与"下次要跑的模式"可以合法地不一致。

## 3. 前端视图盘点

| 视图 | 职责 | 与其它模块关系 |
|------|------|----------------|
| **流量 Traffic** | 会话请求列表、筛选、详情、指纹/Hook/代码 tab | 启动 Lab / AI 分析 / 连接来源；空态引导零配置浏览器 |
| **内嵌浏览器 Browser** | 隔离 Chrome、开始抓包、Hook 面板 | 证据写入当前会话；加密 Lab 可送分析 |
| **AI 分析 Analysis** | 模式选择、Agent 进度、报告、工具轨迹 | 只读会话 + MCP；导出算法包 |
| **请求实验室 Lab** | 重放、规则、代码生成、集合 | 从流量多选进入；规则与 PX 改写衔接 |
| **高级控制台 Advanced** | 阶段引导、TLS 预置、PX、指纹、能力分工表 | 跳转流量/浏览器/设置/分析；Agent 读证工具同源 |
| **设置 Settings** | CA 安装、代理端口、设备接入、出口代理与 TLS 指纹、AI、MCP | 抓包前置条件；分区顺序按「新手最先要的」排列，CA 在最上且默认展开 |
| **Skills** | 内置 Skill 契约预览 | 与分析规划一致 |

## 4. 后端 / 代理能力盘点

| 模块 | 能力 | 自动化 |
|------|------|--------|
| **MITM 代理** | HTTP/1.1·H2、CONNECT 隧道、系统代理可选接管与恢复 | 启动即监听默认 `127.0.0.1:8888` |
| **Root CA** | 每安装独立 CA、本机安装、导出、设备扫码页 | 一键安装；Android 可推送证书与代理 |
| **出站 TLS** | 版本化 ClientHello 预置（rustls）、入站自动选档 | 握手按预置改配方；**不宣称**位级浏览器 JA3 |
| **TLS 指纹** | 入站 JA3/JA4、出站说明 | 会话记录；Agent `shownet_get_tls_fingerprints` |
| **浏览器 Hook** | 脚本前注入网络/加解密 Hook | 与请求按序关联 |
| **AST 加密提取** | Web Crypto / CryptoJS / 国密 SM 等有界片段 | 响应解析自动写入 |
| **PX 控制台** | 解密开关、ecData 拦截、证据列表、结构解码 | 开关影响抓包标记；解码非硬破 |
| **动态防护分析** | WAF/captcha/sensor 聚合、scorecard | Skill 自动启用 |
| **算法重放 / Auto-crawler** | 多语言模板与离线校验 | 分析后导出 |
| **MCP / Agent** | 本地工具 + 可选外部 MCP、grok-build sidecar | 规划后按需调用只读工具 |

## 5. 抓包过程 vs 分析过程（能力分工）

机读表见 `src/advancedConsoleCapabilities.ts`（UI 总览与测试共用）。

**抓包过程（配置与采集）**

- 出站 ClientHello 预置 / 入站自动选档  
- PX 解密、拦截 ecData  
- 浏览器 Hook 注入、代理会话写入  
- TLS 指纹与 PX 证据落库  

**分析过程（只读取证与导出）**

- `shownet_get_tls_fingerprints`、`shownet_get_outbound_tls_status`  
- `shownet_list_px_evidence`、`shownet_decode_px_payload`  
- `shownet_analyze_dynamic_protection`、scorecard、harness  
- Hook / crypto snippets / algorithm replay / code generate  

## 6. 诚实边界（产品与 Agent 文案一致）

- 出站引擎默认 **rustls**；`ja3Parity` / `supportsFullBrowserJa3` 为 false，除非未来接入实测通过的 impersonate 栈。  
- PX / challenge 解码是**结构解析**，不是无密钥硬破。  
- 证书锁定 App 通常只能采连接元数据。  
- Agent 默认**只读取证**；改预置 / PX 开关由用户在 UI 操作。

## 7. 最佳实践清单

1. 先用内嵌浏览器验证产品是否工作，再装 CA 抓 App。  
2. 出站预置优先 `chrome150` 等版本化 id；观察指纹页 `ja3Parity`。  
3. 有 Hook 或加密片段时用 **JS 加密逆向**；有 WAF/captcha 用自动模式让 dynamic-signature 入选。  
4. 报告中的发现点回请求核对后再导出算法包。  
5. 高级控制台按阶段使用，避免空会话上空调参数。
