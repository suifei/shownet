# 真实浏览器测试

`npm run test:browser`（或 `npm run test:all` 跑全部三层）。需要浏览器二进制：
首次运行前执行 `npx playwright install chromium`。

不在 `npm test` 里，因为它需要 dev server 和浏览器二进制，不是所有环境都有。

## 这一层负责什么

前两层都不做**排版**：jsdom 渲染出 DOM 树，但不计算任何几何，也解析不出最终颜色。
所以下面这些失败它们结构上就看不见：

| 检查 | 对应的真实故障 |
|------|----------------|
| 文字被挤压 | `width: 28px` 的图标规则命中了带文字的按钮，菜单每行被压成一个字 |
| 页面横向溢出 | 元素越出窗口右边缘，整页出现水平滚动条 |
| 浮层越界 | 弹出面板在窄窗口下超出可视区 |
| 色彩对比 | 深色主题里前景色不够亮，axe 在 jsdom 中无法运行此规则 |
| 焦点可见 | 键盘 Tab 到某个控件时没有任何视觉指示 |

两个视口都跑：`desktop` 1440×900 与 `narrow` 900×800。窄屏那套响应式规则此前只靠肉眼看过。

## 检测器的写法

「文字被挤压」的判定值得说明，因为**直觉写法是错的**。

第一版用"元素宽度 < 字号 × 2.5"，结果把 `GET`、`PUT`、`8888` 全报成挤压——短标签本来就窄。
第二版改用 `scrollHeight / lineHeight` 估算行数，又把带图标的按钮和包着 `<input>` 的 `<label>` 报了出来——
非文字子元素撑高了盒子却不贡献文字。

最终用 `Range.getClientRects()` **直接数文字渲染出的行盒**，按 top 坐标分桶，
再看每行平均字符数。判定条件是「≥3 行且每行不足 4 个字符」——
真实段落不会长这样，被压窄的标签一定长这样。

验证方式：把当初那条 CSS 规则改回去，检测器精确报出
「集合公共配置」6 个字被压成 6 行。**不能证伪的检测器没有价值**，加新规则时请照此验证。

## 首次接入扫出的问题

- **筛选面板在窄窗口下越界**：它用 `left: 0` 向右展开（应用里其他弹层都是 `right: 0` 向左展开），
  900px 宽度下右边缘超出窗口 104px。桌面尺寸下完全正常，所以之前一直没发现。
- **高级控制台的说明文字对比度 4.44:1**：`opacity: 0.7` 把 `--muted` 拖到了 4.5 门槛以下。
  改用调色板里现成的 `--text-subtle`（5.76:1），不再用不透明度调暗文字。

## 关于视觉快照

**没有引入截图比对。** 跨机器的字体渲染差异会让基线频繁失效，而这个项目正处于活跃改版期，
每次合理的视觉调整都要重刷基线——噪音会淹没信号。
上面这些**断言式**检查表达的是不变量，不会因为一次合理的样式调整而误报。
