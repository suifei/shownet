# 渲染测试

`npm test` 现在跑两层，两层各自能发现对方发现不了的问题。

| 层 | 命令 | 环境 | 断言对象 |
|----|------|------|----------|
| 源码约定 | `npm run test:unit` | `node --test` | 源文件文本、纯函数 |
| 渲染行为 | `npm run test:render` | vitest + jsdom | 真实挂载组件后的 DOM 与交互 |

## 为什么要加第二层

第一层断言的是"源码里写了什么"。它跑得快、能锁住已做的决定，但**无法判断组件实际渲染出什么**。
ShowNet 这轮 UI 重构中，有三个 bug 在第一层全绿的情况下漏了过去：

1. `commitBaseline` 在与 `setState` 同一个 tick 里从 state 读值，读到的是更新前的值——
   设置页的未保存标记因此永远不亮。源码看起来完全正确。
2. 报告标题跟着"模式选择器"走而不是"正在显示的报告"，在模式共享之前一直被掩盖。
3. `.collection-pane-actions button` 的 28×28 规则命中所有后代，把菜单压成一列。

第 1、2 类由本层覆盖。第 3 类是布局问题，jsdom 不做排版，**只有真实浏览器截图能发现**——
仓库里没有常驻的浏览器测试，改动布局时请手动截图确认。

### 这一层已经发现的问题

写测试的过程本身就在做设计审查。按加入顺序：

- **浮动操作栏凭空出现**：流量页会自动选中第一行（为了详情面板有内容）。
  改版前这只是让状态栏多几个图标，改成浮动栏后变成每次加载都弹出一条横跨网格的操作栏。
  修法是区分"用户主动选择"与"自动聚焦"。见 `confirm-and-selection.test.tsx`。
- **确认对话框里两个按钮同名**：关闭 X 与取消按钮的可访问名称都是「取消」。
  用 `getByRole` 查询时会直接撞上这类问题——查询本身在验证可访问性。
- **首次打开 AI 分析时三者不一致**：为保护"用户在别处选的模式"而禁止挂载时采纳报告模式，
  但首次打开并不存在这种选择，结果选择器停在默认值、与报告标题不符。
  修法是区分"默认值"与"用户已选"。见 `analysis-mode.test.tsx`。
- **Skill 编排的流程侧栏没有可访问名称**：`<aside>` 无 label，测试无法干净定位。
  补了 `aria-label` 后测试和读屏都受益。
- **「请求对比」的空态基本不可达**：入口按钮与标签页都已用"恰好两条"硬性守卫。
  空态作为防御性兜底保留，但测试改为覆盖用户真正会遇到的禁用态。

### 可访问性

`a11y.test.tsx` 用 axe-core 扫描全部 6 个主视图与 3 个对话框，违规数必须为 0。
色彩对比是唯一被关掉的规则——jsdom 不做排版也不算计算样式，判不了。

首次接入时扫出的问题（均已修复）：

- **流量网格没有 `role="grid"`**（critical）：里面的 row / columnheader / rowgroup 全是孤儿节点，
  读屏软件看到的是一堆散行而不是表格。同时补了 `aria-rowcount` / `aria-rowindex` ——
  列表是虚拟滚动的，DOM 里只有约 50 行，不声明真实行数会让读屏用户以为总共就这么多。
- **实验室里有两个 `<main>`**：应用外壳已有一个，工作台又嵌了一个（集合面板还有第三个）。
- **标题跳级**：详情面板的路径原本是 `<strong>`，导致里面的 h3 直接从页面 h1 跳过来。

这一层跑得快（全量 77 项约 3 秒），加进 `npm test` 后可以持续挡住回归。

## 约定

- 只测**用户能观察到的行为**：可见文本、可访问名称、禁用状态、点击后的结果。
  不要断言 class 名或内部 state，那是第一层的活。
- 优先用 role 查询（`getByRole`），它同时验证了可访问性。
  写测试时如果找不到合适的 role，通常说明该控件的语义标记有问题。
- Tauri IPC 在 `setup.ts` 里统一 mock。组件在模块加载时就会调 `isTauri()`，
  所以 mock 必须先于任何组件 import 生效。
- 预览构建（`isTauri() === false`）有预置会话与请求，且 `capturing` 初始为 `true`。
  写断言前先确认这些前提，否则容易误判。
